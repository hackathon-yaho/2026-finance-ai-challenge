## MVP 검증 절차 (심사자 관점)

기능명세서 제출본 기준 검증 절차:

1. 배포 URL 접속 → 문진 5문항 응답
2. 샘플 이미지 업로드
3. 판정 화면 확인
4. 문진의 '과거 이력' 응답을 변경 → **판정이 실시간으로 바뀌는지 확인** (TC-04와 동일한 지점)
5. 소명서·체크리스트 생성 확인

샘플 입력값 예시: 입금액 "50만원 미만" + 거래성격 "중고 물건 판매" + 과거이력을 "있음"으로 변경하면 → "기각 가능" 판정으로 즉시 전환되어야 합니다.

## 발표 데모 시나리오 (15분 PT 중 5분)

```
[0:00] 화면에 실제 캡처 4장 업로드
[0:20] 타임라인이 시간순으로 조립되는 장면 — 말없이 보여준다
[0:45] "송장을 빼면 어떻게 될까요" → 붉은 공백 표시 등장
[1:10] 판정 화면 — 3요건 대조 후 도장이 찍힘
[1:30] "이력을 있음으로 바꾸면" → 도장이 '기각 가능'으로 뒤집힘
[2:00] 소명서 화면 — 앞에서 올린 자료가 문장으로 변환됨
[2:40] 협박문자 추가 → 반증 문단이 자동 추가되는 장면
[3:10] "이 서비스는 판정하지 않습니다. 준비를 돕습니다"
```

**핵심**: 조건을 바꿔서 결과가 뒤집히는 장면(TC-04 시나리오)을 반드시 라이브로 보여줍니다. 정적인 결과 화면보다 훨씬 설득력이 있습니다.

## 오프라인 데모 모드 (필수)

발표는 10월 13일 오프라인이며 현장 네트워크는 통제할 수 없습니다. LLM API 장애나 네트워크 문제가 생겨도 전체 플로우(TC-01~05 수준)를 완주할 수 있도록, **사전 저장된 판독 결과로 동작하는 데모 모드**를 반드시 구현합니다. 담당: AI(사전 녹화 응답 세트 준비) + 백엔드(모드 전환 스위치).
