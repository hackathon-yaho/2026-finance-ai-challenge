## MVP 검증 절차 (심사자 관점)

기능명세서 제출본 기준 검증 절차:

1. 배포 URL 접속 → 문진 6문항 응답
2. 샘플 이미지 업로드 → 추출 카드 확인·수정(FR-028)
3. 제출 준비도 점검 화면 확인
4. 문진의 '과거 이력' 응답을 변경 → **준비도가 실시간으로 바뀌는지 확인** (TC-04와 동일한 지점)
5. 소명서 생성 → 문장 클릭 시 근거 원본 이미지 확인 (FR-046)
6. 제출 패키지(6종) 다운로드 확인

샘플 입력값 예시: 입금액 "450,000원" + 거래성격 "중고 물건 판매" + 과거이력을 "있음"으로 변경하면 → "은행 확인 필요" 상태로 즉시 전환되어야 합니다. 입금액은 준비도 산출에 쓰이지 않으므로(`../01-product/reason-type-rules.md` §2) 상태를 뒤집는 값은 과거이력 하나입니다.

## 발표 데모 시나리오 (15분 PT 중 5분)

```
[0:00] 화면에 실제 캡처 4장 업로드
[0:20] 타임라인이 시간순으로 조립되는 장면 — 말없이 보여준다
[0:45] "송장을 빼면 어떻게 될까요" → 붉은 공백 표시 등장
[1:10] 준비도 점검 화면 — 확인 완료·증빙·충돌 대조 후 상태가 표시됨
[1:30] "이력을 있음으로 바꾸면" → 상태가 '은행 확인 필요'로 뒤집힘
[2:00] 소명서 화면 — 앞에서 올린 자료가 문장으로 변환됨
[2:20] 문장을 클릭 → 근거가 된 원본 캡처가 즉시 열림 (이 서비스의 핵심, FR-046)
[2:40] 협박문자 추가 → 협박 수신 사실 문단이 자동 추가되는 장면
[3:10] "이 서비스는 판정하지 않습니다. 준비를 돕습니다"
```

**핵심**: 조건을 바꿔서 결과가 뒤집히는 장면(TC-04 시나리오)과 문장-근거 연결(TC-12)을 반드시 라이브로 보여줍니다. 정적인 결과 화면보다 훨씬 설득력이 있습니다.

## 오프라인 데모 모드 (필수)

발표는 10월 13일 오프라인이며 현장 네트워크는 통제할 수 없습니다. LLM API 장애나 네트워크 문제가 생겨도 전체 플로우(TC-01~06 수준)를 완주할 수 있도록, 환경변수 `DEMO_MODE=true`로 켜지는 **사전 저장된 판독 결과 6종**으로 동작하는 데모 모드를 반드시 구현합니다(`../00-context/spec.md` F11-03).

- `DEMO_MODE=true`일 때는 모든 화면 상단에 "예시 데이터 사용 중 — 실제 AI 분석 결과가 아닙니다" 배지를 고정 표시합니다.
- 실제 사용자 업로드 파일과 데모 데이터를 화면 표시 없이 자동으로 섞지 않습니다.
- 담당: AI(사전 녹화 응답 세트 준비) + 백엔드(모드 전환 스위치). 마지막 날이 아니라 **9월 2일 완성도 작업 때** 함께 만듭니다.

## AI 평가 세트 (F11-05)

배포 전 비식별·합성 이미지 20~30건(채팅/거래내역/배송/협박/흐림/잘림/금액 충돌/악성 지시문 포함)으로 날짜·금액 정확도, 협박 재현율, 근거 연결률, 근거 없는 문장 비율을 측정합니다. PRD §1.4의 AI 품질·안전 지표와 1:1로 대응됩니다. P1 — 컷될 경우 지표 표는 문서에 유지하고 실측만 생략합니다.
