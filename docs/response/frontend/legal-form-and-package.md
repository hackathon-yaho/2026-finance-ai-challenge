## 1. §3-2 4면 증빙목록 — **A 확정. 잡아주셔서 다행입니다**

**A(올린 자료의 목차)가 맞습니다.** 근거는 §3-2에 적어주신 것과 같습니다 — `prd.md` §4.4 매핑표가 *"첨부서류 1 = 타임라인 + 증빙목록 + 원본이미지"* 로 셋을 묶었고, **목록과 실물이 짝을 이루는 구조**입니다.

**제 요청서의 "출처 = `/api/draft`의 `checklist`" 표기가 틀렸습니다.** 그대로 구현했으면 5면을 빼도 미보유 목록이 4면으로 그대로 나갔을 겁니다. **5면만 빼는 걸로는 반쪽**이라는 지적이 정확했습니다.

## 2. §3-1 표지 — **채택합니다**

"직접 첨부 안내"보다 넓혀 표지 한 장으로 만들자는 제안, 받겠습니다. 드신 근거 셋에 하나 보탭니다 — **자필 서명 안내가 PDF 안으로 들어갑니다.** 지금은 화면에만 있어서, 파일만 받아 그대로 보내는 사용자는 서명 없이 제출하게 됩니다.

`spec.md` F7-06에 제안하신 레이아웃 그대로 넣었습니다. **장수는 6면 그대로**입니다.

**금지 조항 하나를 명세에 못박았습니다**: 표지에 **못 갖춘 자료를 적지 않습니다.** 표지를 만들다 보면 "아직 없는 것"을 친절하게 적고 싶어지는데, 그러면 부족자료 체크리스트를 뺀 이유가 표지에서 되살아납니다. TC-35로 회귀 테스트를 걸었습니다.

## 3. §1 서식 11필드 — 그대로 계약에 반영

`mobile` / `email` / `holderName` 3개 신설, 나머지 8개 유지. **"다른 이름을 제안하지 않겠다"** 는 판단에 동의합니다 — 서식 기재란과 1:1로 읽히는 이름이 맞습니다.

`api-contract.md`·`api-spec.md`·`spec.md` F7-06·`prd.md` §4.4·§9 전부 11필드로 동기화했습니다. **8/24 확정 규칙(전부 선택 / 공란 PDF / 필수 표시 금지 / 100자·`birthDate` 형식만 검증)이 11개에 그대로 적용**됩니다.

### 3-1. "신청인과 동일" 체크박스 — 기본 체크 동의

법 제7조 제1항의 주체가 명의인이라 둘이 다른 경우가 예외적이라는 근거, 맞습니다. **체크박스 상태를 계약에 넣지 않은 것**도 옳습니다 — 프론트 폼 상태일 뿐이고 바디에는 최종 문자열만 오면 됩니다. 계약에 그렇게 적었습니다.

## 4. §2 서명 안내 — 확인했습니다

**"따로 챙기실 것"을 별도 블록으로 올리고 F3-07 ③과 이름을 통일**하신 것, 명세로 승격했습니다(`spec.md` **F7-07** 신설). 같은 항목을 화면마다 다르게 부르면 안 된다는 판단이 맞습니다.

**재스캔 안내를 넣으신 것**도 F7-07 본문에 넣었습니다. 인터넷은행이 이메일·팩스 접수라는 §1 지적과 이어지는 부분이고, 이게 빠지면 서명한 종이를 손에 들고 어떻게 보내는지 모르게 됩니다.

경고색을 안 쓰신 판단도 그대로입니다 — 사용자가 뭘 잘못한 게 아니라 절차 안내입니다.

## 5. §3-3 버튼 문구 — 동의

**"버튼에 숫자를 박아두면 구성이 바뀔 때마다 문구가 낡는다"** — 맞습니다. 이번에 실제로 6종 → 구성이 바뀌었고요. 백엔드 문서에서도 "텍스트 5종"이라는 표현을 **"텍스트 면"**으로 바꿨습니다(`prd.md` FR-043 포함).
