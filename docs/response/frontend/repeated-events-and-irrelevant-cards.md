# [AI → 프론트] 회신: §4 반복 이벤트 묶기 — **A안으로 구현했습니다**

- 원본 요청: `../../request/backend/repeated-events-and-irrelevant-cards.md` (프론트 · 2026-08-26)
- 회신: AI · 2026-08-26 (§3·§4·§7 = AI 소관분)

## 결론 — A안(추출 단계에서 묶기) 채택. 계약 반영·구현·실측까지 마쳤습니다

§4의 판단이 맞습니다. **B안은 §3이 안 풀리고, C안은 PDF와 화면이 갈립니다.** 두 근거 모두 그대로 받아들였습니다.

## 1. 계약: 카드에 `recurrence` 신설

`../../02-architecture/internal-api-contract.md` "recurrence" 절에 넣었습니다. 반복이 아니면 `null`이고, 대부분의 카드는 `null`입니다.

```json
"recurrence": { "count": 12, "period": "monthly",
                "first": "2026-01-15T09:00:00+09:00",
                "last":  "2026-12-15T09:00:00+09:00" }
```

| 규칙 | 내용 |
| --- | --- |
| `amount`는 **1회분** | 총액이 아닙니다. 총액을 넣으면 백엔드 금액 대조가 어긋납니다 |
| `occurred_at`은 **`first`** | 타임라인 정렬 기준 |
| **`count`는 AI-server가 계산** | LLM이 센 값을 쓰지 않습니다 — 아래 §2 |

§5에서 말씀하신 "개별 날짜를 버리지 않는다"는 `first`/`last`/`count`로 지켜집니다.

## 2. "12회"를 LLM에게 세게 하지 않았습니다

**LLM은 개별 발생 일시를 나열만 하고, 횟수는 코드가 셉니다.** `count`가 틀리면 **은행에 가는 문서의 숫자가 틀리는 것**이라, 확률적인 값을 그대로 쓸 수 없었습니다.

- LLM 출력: `{ period, occurrences: ["2026-01-15T09:00:00+09:00", ...] }`
- AI-server: 파싱 가능한 일시만 골라 정렬 → `count = 개수`, `first = 첫째`, `last = 마지막`
- 파싱 가능한 일시가 **2개 미만이면 반복으로 보지 않습니다** (근거 부족)

소명서 문장의 "12회"도 사실검증기가 대조합니다 — 횟수를 부풀린 문장은 삭제됩니다(회귀 테스트 포함).

## 3. 같은 날 반복은 묶지 않습니다 — 실측에서 잡은 부작용

구현 직후 평가 세트에서 **의도하지 않은 묶임**이 나왔습니다. `ev-bank-02`(같은 날 1분 간격 입금 3건)가 카드 1장으로 묶였습니다. 규칙("같은 금액·같은 내용·규칙적 간격")에는 들어맞지만, **정기 거래가 아니라 개별 입금**이고 소명에서는 각각이 사실입니다.

**반복 주기가 최소 하루 이상일 때만 묶도록 코드에서 막았습니다.** 프롬프트에도 같은 경계를 적었지만, 프롬프트 준수는 확률적이라 코드 가드를 신뢰 지점으로 뒀습니다.

## 4. §3 지연 — 함께 풀렸습니다

말씀하신 대로 출력이 12건 → 1건이 되면서 지연이 같이 내려갔습니다.

| | 묶기 전 | 묶은 후 |
| --- | --- | --- |
| 자동이체 12개월 캡처 | **10.4초** | **5.1~5.4초** |
| 전체 p95 (28건) | 6.2초 | **5.8~6.8초** |

프론트가 실측하신 15.1초(→`504`)보다 제 쪽 수치가 낮게 나온 건 합성 캡처라 그렇습니다 — **실제 캡처가 더 무겁습니다.** 리허설에서 실제 데모 이미지로 다시 재겠습니다.

## 5. 알려주신 두 조건을 평가 세트에 넣었습니다

**이게 이번 회신에서 제일 고마운 부분입니다.** 제 평가 세트는 제가 만든 합성 이미지라 **제가 생각한 조건까지만** 담고 있었습니다.

| 알려주신 조건 | 제 세트가 못 잡은 이유 |
| --- | --- |
| 한 장에 이벤트 12건 | 제 이미지는 **한 장에 최대 3건**이었습니다. 즉 "p95 5.9초 달성"은 1~3건일 때의 숫자였습니다 |
| 은행 캡처가 `08.19`로 연도 없음 | 제 이미지는 **전부 연도가 있었습니다** |

`ev-many-01`·`ev-noyear-01`로 넣어 회귀로 지킵니다. 세트는 `../../../ai-server/evals/`에 있고 **누구나 열어서 검증하실 수 있습니다** — 기대값(`cases.py`)과 채점 규칙(`runner.py`)까지 전부 저장소에 있습니다.

## 6. §7 확인 — 연도 없는 캡처

`ev-noyear-01`(`08.19  10:07` 3행)로 재봤더니 **연도를 지어내지 않고 `occurred_at: null`을 냈습니다.** 말씀하신 대로 AI 품질 문제가 아니라 원칙대로 동작한 것입니다.

**A안(게이팅)에 동의합니다.** 백엔드가 이미 구현하셨다고 하니 AI 쪽에서 추가할 것은 없습니다. B안(연도 힌트)은 **틀린 연도가 그럴듯하게 은행에 가는** 위험이 있어 저도 반대합니다.

## 7. 프론트가 할 것

계약이 확정됐으니 반복 표기를 렌더해 주시면 됩니다.

- **카드**: `recurrence`가 있으면 배지 (예: "매월 · 12회")
- **3면·4면**: 각 한 줄. §5에서 말씀하신 "매월 15일 65,890원 · 12회" 형태가 정확합니다
- `recurrence`가 `null`인 카드가 대부분이니 **없을 때가 기본**입니다

§2(무관 거래)는 백엔드가 현행 유지로 결정하셨고 AI 쪽 변경 없습니다.
