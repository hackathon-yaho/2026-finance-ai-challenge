## 2. §4 심사 기간 운영 — **백엔드도 같이 지킵니다**

> 그 기간에는 프론트가 main에 푸시하지 않겠습니다.

**백엔드도 같은 이유로 푸시하지 않겠습니다.** Render가 main 자동 배포로 걸려 있어 푸시하면 **심사 중에 재기동**이 일어납니다. 프론트는 화면이 바뀌는 정도지만 백엔드는 **접속 불가 구간**이 생깁니다 — 대회 결격과 직결됩니다.

`backend/docs/phase-6-infra-ops.md` 심사 기간 운영에 항목으로 넣었습니다. **9/6 밤까지 모든 배포를 끝냅니다.**

로테이션(9/7~9/11 매일 아침 3개 URL 확인)은 그대로 참여합니다.

## 3. §6 로드맵 표기 정정 — **고쳤습니다**

> `roadmap.md`의 프론트 과제 표에는 회신 위치가 `../response/frontend/`로 적혀 있는데, 그건 **프론트가 읽는 폴더**입니다.

**맞습니다. 제가 틀리게 적었습니다.** `response/README.md`가 "폴더 이름 = 이 문서를 읽을 사람"으로 정한 규칙인데, 로드맵에서 제가 그걸 어겼습니다.

이 문서를 `response/backend/`에 두신 판단이 규칙대로입니다. 로드맵 표기를 고쳤고, **문서 소유가 백엔드라 프론트가 손대지 않으셨다**는 것도 매몰 방지 원칙 그대로입니다.

## 4. 확인한 것

§3에서 배포 직후 검증하신 내용(HTTP 200, 화면 렌더, 번들 해시 일치) 확인했습니다. **번들 해시로 최신 커밋 반영을 확인**하신 방법이 좋습니다 — "배포됐다"와 "최신 코드가 배포됐다"는 다른 얘기인데 그걸 구분하셨습니다.

**SPA fallback을 넣지 않은 판단**도 맞습니다. 라우터가 없으니 경로가 `/` 하나뿐이고, 필요 없는 설정을 미리 넣으면 나중에 왜 있는지 모르는 파일이 됩니다. 라우터 도입 시 추가한다는 조건까지 적어주셨으니 그대로 두면 됩니다.
