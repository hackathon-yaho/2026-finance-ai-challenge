## 2. §7-② `/api/draft/revise` 8/29~8/31 — **가능합니다**

**일정을 당기신 판단을 받습니다.** §5-1의 근거가 맞습니다 — 읽기 전용만으로는 사용자가 틀린 문장을 **발견만 하고 고치지 못한 채** 다운로드하고, 그러면 "AI 초안 · 사용자 확인 완료" 표기도 "봤다"까지만 사실이 됩니다.

**종전 회신을 뒤집으면서 착수 전에 알려주신 것**이 특히 도움이 됐습니다. 구현 중에 알았으면 계획을 다시 짜야 했습니다.

`roadmap.md` 백엔드 확정 작업 **19번**으로 8/29~8/31에 박았습니다.

> **어려워지면 즉시 알리겠습니다.** 그 경우 §5-3대로 읽기 전용 + 문장 제외로 먼저 가고 자유 편집만 9/1~9/2로 되돌리면 됩니다. **`excludedSentenceIds`는 `/api/package/text` 바디만으로 되므로 revise가 밀려도 살아남습니다** — 이 안전망을 남겨두신 게 좋습니다.

### 2-1. §3 제외 방식 — **`excluded` 토글 채택**

`text: ""`를 쓰지 않는 이유 두 가지 다 동의합니다. 특히 **"되돌릴 수 없다"** 가 결정적입니다 — 미리보기는 사용자가 이것저것 시도해보는 화면인데 되돌리기가 없으면 시도 자체를 못 합니다.

**`text`와 `excluded`를 분리**한 것도 그대로 계약에 넣었습니다. 한 필드에 두 의미를 넣지 않습니다.

### 2-2. §1 근거 미매칭 — B 확정, **PRD를 고쳤습니다**

**FR-045 ③이 "매칭 안 되는 문장 자동 삭제"라고 단정적으로 적혀 있어서, 이대로 두면 구현자가 사용자 수정 문장까지 지웁니다.** 요구사항 본문 변경이라 PRD 개정 사안으로 처리했습니다.

> ③ … **단 이 규칙은 LLM이 생성한 문장에만 적용한다.**

**"A는 오히려 사용자 입력을 `user_text`로 인정하지 않는 셈"** 이라는 지적을 개정 사유에 그대로 옮겼습니다. ⑤가 이미 `user_text`에 "본인 진술"을 규정하고 있으니, 살리는 쪽이 규정을 따르는 것이 맞습니다.

**§1-1 배지 변화를 계약에 넣었습니다.** "경고 문구는 읽고 넘기지만 배지가 바뀌는 건 눈에 보인다"는 게 정확한 관찰이라, `api-contract.md`와 `api-spec.md` 양쪽에 **표로** 넣었습니다.

## 3. §7-③ 면별 항목·정렬 기준 — **정의했습니다**

**"같은 면을 두 사람이 각자 그리기 때문에 기준이 필요하다"** — 이게 맞습니다. `spec.md` F8-01에 넣었고, **PDF가 단일 출처**라는 것도 명시했습니다.

| 면 | 항목 | 정렬 |
| --- | --- | --- |
| 표지 | "이 문서에 포함된 것" / "신청인이 따로 첨부하는 것" | 고정 |
| 1 | 서식 11필드 | 서식 순서 |
| 2 | 진술서 본문 (`excludedSentenceIds` 제외) | 문장 생성 순서 |
| 3 | 일시 · 행위 주체 · 요약 · 금액 | `occurred_at` 오름차순, 동시각은 F5-01 tie-break |
| 4 | 순번 · 자료 유형 · 확인된 일시 · 한 줄 요약 | **5면 이미지 순서와 일치** |

**물어보신 3가지에 답하면**

| 질문 | 답 |
| --- | --- |
| 3면에 `gaps`를 표시하는가 | **아니오.** 부족자료를 뺀 것과 같은 이유입니다 — "못 갖춘 것"을 제출본에 적지 않습니다. 공백은 화면에만 |
| 4면에 파일명을 넣는가 | **아니오.** 지적하신 그대로 개인정보가 섞입니다(`카톡_김철수_20260901.png`). 금지 조항으로 명문화했습니다 |
| 표지에 무엇을 적는가 | 포함된 것 + 따로 첨부하는 것. **못 갖춘 것은 적지 않습니다** (TC-35) |

**1면 재현 규칙**도 함께 정의했습니다 — 레이아웃 유지 / 접수번호·접수일자 **공란+음영** / 수신처에 `account.bank` / 작성일자는 서버 생성 / 서명란 공란.

**§4-1 ①(1면을 HTML로 재현하지 않음)에 동의합니다.** "같은 법정 서식을 두 곳에서 구현하면 한쪽만 고쳤을 때 조용히 어긋난다"가 맞고, **"사용자가 확인해야 할 것은 자기가 입력한 값이지 표 선의 위치가 아니다"** 라는 판단이 특히 정확합니다. 명세에 그대로 옮겼습니다.

## 5. §4-2 "실제 문서" 보기 — 확인했습니다

미리보기와 다운로드가 **같은 함수를 쓰게** 하신 것이 핵심입니다. 따로 만들면 결국 갈립니다.

**iOS 사파리 blob PDF 문제** 때문에 `<iframe>`을 피하고 pdf.js로 가신 것도 기록해둘 가치가 있어 `spec.md` F7-08 개발 주의에 옮겼습니다 — 나중에 누가 "iframe이 더 간단한데"라고 생각할 지점입니다.

**§4-1 ② 9/6 점검 항목** — `roadmap.md` 9/6 최종 점검에 **"생성된 PDF를 실제로 열어 한글이 정상 렌더되는지 확인"** 을 명시 항목으로 넣었습니다. `phase-5`·`phase-6`에도 같은 문구를 달았습니다. **"HTML 미리보기는 브라우저 폰트로 그려서 이 사고를 구조적으로 못 잡는다"** 는 이유를 함께 적었습니다 — 이유가 없으면 다음 사람이 "실제 문서 보기가 있는데 왜 또 확인하나"로 지웁니다.
