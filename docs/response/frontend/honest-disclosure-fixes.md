## 1. §2-1 "최대 3년" — **1차 출처 확보 실패. 숫자를 넣지 않습니다**

요청하신 대로 찾아봤습니다. **결과를 그대로 적습니다.**

| 시도 | 결과 |
| --- | --- |
| 은행연합회 소비자포털 FAQ 직접 열람 | **기간에 대한 언급이 없음** — 신고 절차·은행 연락처·환급 절차만 있습니다 |
| 도메인 한정 검색 (`kfb.or.kr`, `fss.or.kr`, `fsc.go.kr`, `law.go.kr`) | 규약 원문에 도달하지 못했습니다 |
| 일반 검색 | 3년이라는 수치는 **블로그·법률상담 사이트에만** 나옵니다 |

**그리고 더 결정적인 게 있습니다 — 2차 출처끼리 값이 다릅니다.**

- 어떤 곳은 **"최대 3년"**
- 어떤 곳은 **"최소 3년"**

최대와 최소는 사용자에게 정반대의 의미입니다. **"3년이면 끝난다"와 "3년은 기본이다"** 는 삶의 계획이 달라지는 차이인데, 우리가 어느 쪽인지 모르는 상태입니다. 이 상태로 숫자를 쓰면 절반의 확률로 **틀린 안내를 확신에 찬 톤으로** 하게 됩니다.

**"한동안"으로 확정합니다.** PRD §2.7을 근거로 드신 것도 맞습니다 — 소액 금액 기준을 추정하지 않기로 한 서비스가 여기서만 후기 근거로 단정하면 앞뒤가 안 맞습니다.

### 반영

- `spec.md` **F9-03 신설** (사기이용계좌 등록 제한 안내) — 화면은 이미 구현하셨으니 명세를 뒤따라 만든 것입니다. 위치(S05), 문구 원문, **"기간 수치 금지"**, **"해제 경로 병기 필수"**, 중립색을 전부 적었습니다
- `reason-type-rules.md` **§4-1 신설** — 금지 문구 원칙에 **시간·후속 불이익** 항목 추가. 요청서 §5로 주신 건입니다
- 두 곳 모두에 **"1차 출처를 확보하면 그때 숫자를 넣는다"** 를 남겼습니다. 지금 상태가 최종 결론이 아니라 **확인 못 한 상태**라는 걸 기록으로 남겨야 나중에 누가 다시 블로그를 보고 넣지 않습니다

## 2. §1 5영업일 카피 — 반영 확인

**"은행이 판단할 수 있는 형태로"** — 이게 더 정확합니다. 숫자를 뺐는데 주장이 약해지지 않았다는 판단에도 동의합니다. **심사 기간은 우리 기능이 아니라 결과**입니다.

통계 행에 **"해제 시점은 아니에요"를 숫자 바로 옆에 붙이신 것** — 배치 판단이 좋습니다. 다른 데 적으면 숫자를 본 사람과 설명을 읽는 사람이 갈린다는 게 정확합니다.

### `notices` 고정 문구 — **서버가 내려줍니다**

물어보신 항목입니다. 말씀하신 쪽이 맞습니다.

- `api-contract.md`에 **`notices`가 서버 단일 소스**임을 절로 명시했습니다. 프론트는 받은 문자열을 **순화 없이 그대로** 노출합니다
- `spec.md` **F6-05 고정 문구를 다시 썼습니다** — 요청하신 "심사 결과 통보"와 "지급정지 해제" 분리 반영

| | 문구 |
| --- | --- |
| 종전 | "…5영업일 내 심사결과를 통보합니다. 자료 보완이 필요한 경우 처리기간이 추가될 수 있으며, **5영업일 내 지급정지 해제를 보장하는 것은 아닙니다.**" |
| **지금** | "…5영업일 내 **심사 결과를 통보**합니다. 자료 보완이 필요한 경우 처리기간이 추가될 수 있습니다.<br>**심사 결과 통보와 지급정지 해제는 다릅니다.** 통신사기피해환급법 제8조 제2항에 따라, 피해자에게 통보한 날부터 2개월이 지나기 전에는 지급정지를 종료할 수 없습니다. **5영업일 내 해제를 뜻하지 않습니다.**" |

**종전 문구의 문제**는 "보장하지 않는다"까지만 적어서 **왜 5영업일이 지나도 안 풀리는지**를 설명하지 못한 것이었습니다. 법 제8조 제2항의 2개월 제한이 별도로 작동한다는 사실이 빠지면, 사용자는 "심사가 끝났다는데 왜 계좌가 그대로냐"에서 서비스를 불신하게 됩니다.

## 3. §3 보존 지침 — 명세로 승격

**"F5-04는 판독이 끝난 뒤 제안이고, 복구는 자료를 모으는 시점에 필요하다"** — 이 구분이 정확합니다. 제가 요청서에 F5-04 얘기를 꺼낸 게 잘못된 연결이었습니다. 판독 후에 "대화 백업을 찾아보세요"라고 하면 이미 업로드를 마친 사용자가 처음으로 돌아가야 합니다.

`spec.md` **F10-06 신설**(자료 보존·복구 안내)로 명세화했습니다. 위치(S02 상단, 파일 선택 위), 두 문구를 한 블록으로 묶는 것, **"F5-04와 다르다"는 구분**, 그리고 **메신저 이름·메뉴 경로를 특정하지 않는다**는 금지 조항까지 적었습니다.

> 메뉴 경로를 안 쓰신 이유("앱이 업데이트될 때마다 틀린 안내가 된다")는 명세에 남길 가치가 있어 그대로 옮겼습니다. 나중에 누가 친절하게 경로를 넣고 싶어질 지점입니다.

**화면 부담이 오히려 줄었다**는 것도 확인했습니다 — F3-07·F10-06이 같은 화면에 오는 구조라 `spec.md` F10-06 "연관" 행에 적어뒀습니다.
