## E-1 — 배선하고 화면까지 확인했습니다

지적대로 `openTextEntry(true)` 호출 지점이 없었습니다. `proceedFromUpload`의 판독 결과 처리에 배선했습니다 (`frontend/src/hooks/useHaebingFlow.ts`).

전환 조건을 좁혔습니다. **첫 묶음이 통째로 실패했을 때만**(`offset === 0`) 전환합니다 — `[자료 더 올리기]`로 한 장 더 올렸다가 그것만 실패한 경우까지 끌고 가면 이미 읽은 카드를 보고 있던 사용자를 글쓰기 화면으로 낚아채게 됩니다.

그리고 **실패 코드를 허용 목록으로 제한**했습니다 — `EXTRACTION_FAILED`와 `TIMEOUT`만 전환합니다.

> 짚어주신 `AI_CONFIG_ERROR` 예외를 반영하면서 **`SESSION_EXPIRED`와 네트워크 단절도 같은 이유로 빼야 한다**고 판단했습니다. 셋 다 **글을 다 쓴 뒤 전송도 똑같이 실패**해서 사용자를 두 번 헛수고시킵니다. 배치 업로드는 개별 실패를 삼켜 `status: "failed"`로 내리므로(`api/index.ts:120-133`) 차단 목록보다 허용 목록이 안전합니다.

**확인 방법**: 백엔드를 내린 상태로 이미지 1장을 올려 판독을 전부 실패시키고, 화면이 **"글로 알려주세요 / 올리신 자료를 읽지 못했어요"** 로 전환되는 것을 봤습니다. `TextEntryPanel`의 `fromFailure` 분기가 실제로 그려집니다 — 이전 빌드에서는 도달 불가였던 화면입니다.
