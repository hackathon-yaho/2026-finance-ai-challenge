## 1. 텍스트 5종 PDF 생성 주체 — **서버 생성이 맞습니다**

백엔드 판단대로 `spec.md` 총괄표의 `F8-01 담당 = C`가 표기 오류입니다. 대조해보니 **나머지 6개 지점이 전부 서버 생성을 전제**하고 있고, 총괄표 한 칸만 어긋나 있습니다.

| 근거 | 내용 |
| --- | --- |
| `spec.md` F7-06 분담 | ①~④,⑥ = 서버 PDF 생성(F8-01) / ⑤ = 브라우저 |
| `spec.md` F8-01 라이브러리 | 서버 OpenPDF 또는 Apache PDFBox |
| `spec.md` F8-01 개발 주의 | Render 컨테이너 한글 폰트 — 프론트에는 해당 없는 제약 |
| `prd.md` FR-047 수용 기준 | "텍스트 5종은 서버 PDF, 원본 이미지 페이지는 브라우저가 병합" |

**총괄표 `F8-01` 담당은 `A`가 맞습니다.** `F7-06`은 이미 `A/C`로 올바르게 적혀 있어 손댈 필요 없습니다.

문서 수정은 요청서에 적힌 대로 **백엔드가 `spec.md` 총괄표와 `api-contract.md`를 함께 고쳐주세요.** 같은 파일을 양쪽에서 고치면 충돌하므로 프론트는 이 두 파일을 건드리지 않았습니다.

### 1-1. `GET` → `POST` 변경 동의합니다

`prd.md` §4.4 필드 매핑상 신청인 인적사항 4개와 계좌 정보 4개가 "사용자 직접 입력(서비스 미저장)"이라 `GET` 쿼리로는 실을 수 없다는 지적이 맞습니다. **PDF 생성에만 쓰고 세션·DB·로그에 남기지 않는다**는 전제도 그대로 유지해주세요.

**요청**: 계약에 **요청 바디 필드명을 명시**해주세요. 지금은 서식 항목의 한글 이름만 있어서 프론트가 임의로 키를 정하면 어긋납니다. 아래 형태를 제안하며, 다른 이름을 쓰셔도 계약에만 적히면 그대로 맞추겠습니다.

```json
{
  "applicant": { "name": "", "birthDate": "", "address": "", "phone": "" },
  "account":   { "bank": "", "branch": "", "depositType": "", "accountNumber": "" }
}
```

부수 확인 2건도 계약에 적어주시면 좋겠습니다.
- 이 8개 필드가 **필수인지 선택인지** — 사용자가 계좌번호를 모르는 경우가 실제로 있습니다. 빈 값이면 해당 칸을 공란으로 둔 PDF가 나오는지, `400`인지 정해주세요. 프론트 폼 검증이 여기에 달려 있습니다.
- 응답이 `application/pdf` 바이너리인지 확인합니다. 프론트는 이걸 `pdf-lib`에 그대로 먹입니다.

### 1-2. 프론트가 맡는 범위 (확인차 명시)

- `pdf-lib`으로 서버 PDF + 브라우저 생성 이미지 페이지 병합 → 단일 PDF 다운로드
- 원본 이미지 페이지 생성 (F7-06 ⑤ — 브라우저 blob에서)
- 병합 실패 시 폴백: 텍스트 PDF 다운로드 + 원본 이미지 개별 저장 안내
- **별지 제4호서식 8개 필드 입력 폼** — 현재 UI에 없어서 신규로 만듭니다

### 1-3. 프론트 현재 상태 (일정 공유)

숨기지 않고 알립니다. 지금 프론트는 **UI 프로토타입 단계**이고 이 영역은 다음과 같습니다.

- `pdf-lib` 미설치, PDF 관련 코드 없음
- "제출 패키지 6종 내보내기" 버튼은 토스트만 띄우는 스텁
- 8필드 입력 폼 없음

`roadmap.md` 기준 8/29~8/31 "문서 생성" 구간에 착수합니다. `GET /api/package/text`가 `POST`로 확정된 계약이 그 전에 나오면 폼과 병합을 한 번에 붙일 수 있습니다.

## 2. F5-02 병합 승인 엔드포인트 — 계약 형태 동의

`POST /api/timeline/merge`, 요청 `{ mergeGroupIds, approved }`, 응답 갱신된 타임라인 — 이대로 진행해주세요.

회신 전까지 병합 후보 산출까지만 하고 `GET /api/timeline` 응답에 후보를 담아두겠다는 절충이 좋습니다. **프론트가 그 필드를 무시하면 그대로 스코프 컷이 되는 구조**라 양쪽이 서로를 기다리지 않아도 됩니다.

한 가지만 맞춰둡니다. **F5-02를 컷하면 프론트의 병합 후보 제시 UI도 같이 컷합니다.** 승인 엔드포인트만 살아 있고 부르는 화면이 없는 상태가 되지 않도록, 컷 결정이 나면 이 문서에 회신 주세요.

**요청**: `GET /api/timeline` 응답의 후보 목록 필드명과 구조를 계약에 적어주세요 (예: `mergeCandidates: [{ groupId, eventIds, reason }]`). 지금은 정의가 없어 프론트가 UI를 미리 설계할 수 없습니다.

## 3. 확정 통보 5건 — 전부 수용

### 3-1. `X-Session-Hash` — 수용

프론트에 현재 API 호출 코드가 한 줄도 없어 통신 레이어를 새로 만듭니다. 헤더 주입은 그 레이어에서 일괄 처리하므로 추가 비용이 없습니다. 쿠키를 피한 판단(정적 호스팅 ↔ Render 도메인 분리, `SameSite=None` 리스크)에 동의합니다.

`410 Gone` + `SESSION_EXPIRED` 시 재업로드 안내는 `roadmap.md` 리스크 레지스터의 **"원본이 필요합니다. 다시 올려주세요"** 문구와 같은 처리로 묶어 구현합니다. 새로고침으로 blob이 날아간 경우와 사용자에게는 같은 상황이기 때문입니다.

### 3-2. `deadline` 백엔드 계산 — 수용

프론트는 **`notice` 문자열을 그대로 출력**하고 순화·축약하지 않습니다.

참고로 현재 프로토타입은 `src/lib/deadline.ts`에서 문구를 클라이언트가 만들고 있습니다. **연동 시 이 파일은 폐기**하며, 서버 문구와 다르더라도 서버 값을 따릅니다. 목업 문구가 계약에 영향을 주는 일은 없습니다.

`date`/`daysLeft`가 `null`(공고일 미입력)인 경우에도 `notice`는 항상 내려온다는 전제로 화면을 짭니다. 아니라면 알려주세요.

### 3-3. `409 UNCONFIRMED_FIELDS` — 수용

프론트 차단(UX) + 서버 거부(무결성) 이중 방어에 동의합니다. 정상 흐름에서는 뜨지 않겠지만 에러 핸들러에 케이스를 넣어둡니다. "그 외 미확인 카드는 서버가 통과시키고 준비도 입력에서만 제외" — 경고 문구는 기존대로 프론트가 노출합니다.

### 3-4. `/api/evidence` 이미지 1장씩 병렬 — 수용

프론트 구조와 잘 맞습니다. 마스킹이 이미 **파일 단위 큐**로 돌아가고 있어서 장당 POST가 자연스럽게 붙습니다. SSE를 새로 만들지 않은 판단에 동의합니다.

**세션당 누적 10장 제한을 프론트에도 실제로 구현했습니다.** 지금까지는 "최대 10장"이 안내 문구로만 있고 코드로 막혀 있지 않아 11장째에 `400`을 맞을 수 있었습니다. 이제 초과분은 전송 전에 프론트가 잘라냅니다.

**전송 이미지 크기가 커집니다 — 확인 부탁드립니다.** 프론트가 그동안 `spec.md` F3-01 처리 ①(장변 1600px 리사이즈)을 구현하지 않고 있었습니다. 그 결과 **전송 해상도가 사용자 화면 크기와 DPR에 좌우되어**, 데스크톱 1x 모니터에서는 세로 스크린샷이 **199×431**까지 줄어든 채 나갔습니다. 그 해상도로는 계좌번호·시각·금액을 사람도 못 읽습니다. F4-01 판독 정확도가 이것 때문에 낮게 나왔다면 원인이 여기입니다.

이번에 스펙대로 고쳐서 **장변 1600px 고정**이 됐습니다(위 스크린샷 기준 739×1600, 브라우저 실측 확인). 대신 **장당 페이로드가 수십 배로 늘어납니다.** 실제 대화 캡처는 장당 300KB~1MB, 10장이면 최대 10MB 수준입니다.

- **Spring Boot 기본값 `spring.servlet.multipart.max-file-size`는 1MB**라 그대로 두면 정상 이미지가 `400`으로 떨어집니다. 파일당 10MB(F3-02 ③)에 맞춰 올려주세요.
- Render 프록시의 요청 바디 상한도 함께 확인 부탁드립니다.
- 포맷은 **PNG**입니다. 텍스트가 많은 캡처라 JPEG 링잉이 판독에 불리해서 PNG를 유지했습니다.

**요청**: **프론트가 동시에 던져도 되는 요청 수의 상한**을 정해주세요. "AI-server 최대 4 동시"는 적혀 있지만 그건 백엔드→AI 구간이고, 프론트→백엔드 구간의 상한이 없습니다. 프론트가 10장을 한꺼번에 쏘면 백엔드에서 큐가 쌓이는지, 아니면 프론트가 3~4개씩 끊어 보내야 하는지 알려주세요.

### 3-5. `demoMode` / `smallAmountNotice` — 수용

- `demoMode`: `TopBar`에 이미 `showDemoBadge` 플래그를 `false`로 두고 "백엔드 연동 후 API 응답 값으로 대체" TODO를 달아둔 상태입니다. `POST /api/session` 응답 필드로 확정된 값을 그대로 물리면 됩니다.
- `smallAmountNotice`: 준비도 화면에 자리를 만듭니다. **"판정이 아니라 정보 제공"** 단서에 맞춰 준비도 배지와 시각적으로 분리해 배치하고, 문구는 그대로 출력합니다.

## 4. CORS — 배포 도메인 미정, 로컬부터 열어주세요

프론트 배포 도메인은 **아직 확정되지 않았습니다.** `deployment-and-uptime.md` 기준 9/5까지가 프론트 과제이고 호스팅(Vercel/Netlify/Cloudflare Pages)을 아직 고르지 않았습니다. 확정되는 즉시 이 문서에 회신하고, `role-assignment.md` 규칙대로 `api-contract.md`에 등록 요청하겠습니다.

**그 전에 `http://localhost:5173`(Vite 개발 서버 기본 포트)을 먼저 허용 origin에 넣어주세요.** 도메인 확정을 기다리면 로컬 연동 착수가 9/5까지 막힙니다.

미리 알려둘 사항 하나 — Vercel/Netlify는 **브랜치마다 프리뷰 서브도메인이 새로 생깁니다.** 프로덕션 도메인 하나만 등록하면 프리뷰 배포에서 전부 CORS에 막힙니다. 와일드카드 패턴을 허용하실지, 아니면 프론트가 프로덕션 도메인 하나만 쓰고 프리뷰는 로컬로 대체할지 정해주세요. 후자여도 프론트는 문제없습니다.

## 5. 프론트가 이번에 고친 문서·코드

- `spec.md` F2-01 — 제목의 "문진 5문항"을 **6문항**으로 수정 (본문·문항표는 원래 6개였습니다). 같은 오타가 있던 `spec.md` 기능 트리·총괄표·세션 보관 항목, `prd.md` FR-045 근거 유형 설명도 함께 정정했습니다.
- `spec.md` F2-01 — 6문항을 **3문항씩 2개 서브스텝으로 나눠 제시**하도록 화면 구성과 수용 기준을 반영했습니다. 계약(`POST /api/intake` 6필드)에는 영향이 없습니다.
- `spec.md` F2-02 — 응답 요약을 "우측 시트" 대신 **다음 서브스텝 상단 요약 칩**으로 제시하도록 반영했습니다 (모바일 우선 단일 컬럼 레이아웃).
코드 쪽은 `spec.md` F3-01·F3-02가 요구하는데 구현돼 있지 않던 것들을 채웠습니다. 계약에 영향을 주는 항목은 §3-4에 적었습니다.

- **장변 1600px 리사이즈 적용** (F3-01 처리 ①) — 내보내기 해상도가 더 이상 보는 사람 화면에 좌우되지 않습니다.
- **결과를 Blob + object URL로 보관** (F3-01 처리 ③) — base64 문자열로 들고 있어서 `roadmap.md`가 요구하는 "사용 후 blob URL revoke"를 할 대상 자체가 없었습니다. 이제 삭제·재시작·이탈 시 해제합니다.
- **파일 검증 신설** (F3-02) — 타입 화이트리스트, 파일당 10MB, **매직바이트 확인**, 세션당 10장. 드래그앤드롭은 `accept` 속성을 우회하기 때문에 검증이 없으면 그대로 통과했습니다.
  - 다만 **매직바이트 검사는 서버에서도 해주세요.** 프론트 검사는 사용자 실수를 막는 용도이고, 위조 파일을 실제로 막는 건 서버 몫입니다.
- **손상된 이미지 처리** — 로드 실패 시 안내 없이 "불러오는 중…"에서 멈춰 있었습니다(unhandled rejection). 이제 사유를 띄우고 그 파일만 건너뜁니다.

브라우저 실측으로 20개 항목(2쪽 문진 이동, 위조 파일 거부, 1600px 리사이즈, 마스킹 좌표 스케일, 마스킹 영역 복원 불가, blob 해제)을 확인했습니다.
