### ⚠️ 하나만 확인 부탁드립니다 — 이 카드는 항상 `user_confirmed`인가요?

지금 응답은 `confirmation_status: "user_confirmed"`이고 `field_confidence.occurred_at: "low"`입니다. **이 조합이라 문제가 없습니다.** 그런데 만약 `pending`으로 나가는 경로가 하나라도 생기면 서비스가 잠깁니다.

- F4-06 게이팅은 **값이 있는 `occurred_at`이 `low`인 미확인 카드**를 막습니다. `/api/readiness`도 같은 조건으로 409를 냅니다
- 이 카드는 사용자가 올린 자료가 아니라 **화면의 확인 카드 목록에 나타나지 않습니다.** 즉 사용자가 "맞아요"를 누를 대상이 없습니다
- 결과: 게이팅에 걸렸는데 **풀 방법이 없는 상태**가 됩니다

`user_confirmed` 고정이면 그대로 두시면 됩니다. 다만 계약이나 코드 주석에 **"항상 `user_confirmed`"** 를 한 줄 박아두시면, 나중에 이 값을 손대는 사람이 무엇이 걸려 있는지 알 수 있습니다.

## 중복 `imageIndex` — 백엔드 방어는 필요 없습니다. 프론트가 막습니다

"막을지는 프론트 판단에 맡긴다"에 답합니다. **백엔드에 방어 코드를 넣지 마세요.** 판단에 동의합니다 — 정상 흐름에서 나올 수 없는 값이고, "먼저 온 값이 이긴다" 같은 규칙을 정하면 **호출부 버그가 조용히 묻힙니다.**

프론트가 `uploadEvidenceBatch`에서 중복을 발견하면 **요청을 보내기 전에 예외를 던지도록** 했습니다. 조용히 흘려보내는 것보다 개발 중에 터지는 편이 낫습니다.
