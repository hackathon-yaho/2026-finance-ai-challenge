- 원본 요청: `../../request/frontend/page4-grouped-by-origin.md` (백엔드 · 2026-08-26)

**§3-1 그대로 맞췄습니다.** "① 정리해서 보기"가 4면을 원본 단위로 그립니다. 브라우저에서 두 경로 다 확인했습니다.

## 1. 반영 — `PreviewSheet.tsx` 4면 블록

지적하신 대로 저희가 4면을 **별도 HTML로 그리고 있었고**, 카드 단위였습니다. `source_image_index`로 묶도록 다시 썼습니다. 규칙은 §2를 그대로 옮겼습니다.

- **그룹핑 키**: `source_image_index`. 오름차순 정렬, `null`은 맨 뒤
- **자료 유형**: 그룹 첫 카드의 `source_type` 라벨. `null` 그룹은 "본인 서술"
- **확인된 일시**: 아는 `occurred_at`만 모아 `A ~ B`. 전부 같으면 하나만, 전부 모르면 "시각 미상", 일부만 모르면 뒤에 `(시각 미상 N건 포함)`
- **요약**: 한 장이면 그 카드 요약 그대로, 여러 장이면 `N건 확인됨`

그룹핑 **전에** 거르는 것 두 가지는 종전과 같습니다 — 미확인(`pending`) 카드, 그리고 `intake` 카드(4면 제외 · 3면 포함).

## 2. 확인한 결과

**원본 4장 · 각 1건** (한 장짜리 그룹이 요약을 그대로 쓰는지):

```
1. 자동이체 내역  원본 1번  2026.08.15 09:00  통신비 자동이체 출금 · 12개월째
2. 대화 캡처      원본 2번  2026.09.01 13:40  구매자가 판매 여부를 문의
3. 입출금 내역    원본 3번  2026.09.01 14:12  물품대금 입금
4. 배송·운송장    원본 4번  2026.09.01 16:05  택배 송장 접수
```

**텍스트 직접 입력 · 카드 3장** (`null` 그룹이 한 줄로 합쳐지는지, 부분 미상 표기가 붙는지):

```
1. 본인 서술  2026.09.01 (시각 미상 2건 포함)  3건 확인됨
```

카드 3장이 1줄로 줄었고, `occurred_at`을 아는 1건만 날짜로 나오고 나머지 2건이 괄호로 붙습니다. 원본 이미지가 없는 경우라 "뒤에 원본 이미지가 붙어요" 꼬리말도 같이 사라집니다.

날짜 범위(`A ~ B`)는 목 데이터로는 한 원본에 카드가 여러 개인 조합이 안 나와서 화면으로 못 봤습니다. 실측하신 예시(`2025-09-15 00:00 ~ 2026-08-15 00:00`)와 같은 규칙으로 짰고, 실제 이미지로 테스트할 때 다시 보겠습니다.

## 3. 후속 작업

**없습니다.** 계약 변경이 없어 저희 쪽 타입·어댑터는 손대지 않았고, "② 실제 문서" 뷰는 말씀대로 서버 PDF를 그대로 그려서 자동 반영입니다.

한 가지만 남겨둡니다 — 4면이 원본 단위가 되면서 **"한 줄 = 원본 한 장"이 이제 거의 성립하지만 두 경우는 예외**입니다. 텍스트 입력 그룹(`null`)에는 붙일 원본이 없고, 원본은 있는데 그 원본의 카드가 **전부 미확인이면 그 줄 자체가 사라집니다**. 그래도 이미지 자체는 PDF 뒤에 붙는 것으로 알고 있어서, 목록에 없는 이미지가 뒤에 나오는 상태가 됩니다. 저희 미리보기도 같게 동작하도록 뒀습니다 — 서버와 어긋나지 않는 쪽이 우선이라, 바꿔야 한다면 서버 쪽 결정을 따라가겠습니다.
