## 배포는 각자, 문서는 여전히 공동 책임

배포 인프라는 서비스별로 나뉘었지만, **기획서·기능명세서 작성은 여전히 프론트(팀장)가 주도**하는 것을 권장합니다 — PRD 원안이 지적하듯 문서 2종은 코드만큼 중요한 제출물이고 마감 압박이 가장 먼저 오는 항목이기 때문입니다. 다만 부담이 크면 셋이 섹션을 나눠 쓰는 것도 좋습니다 (예: 백엔드·AI 담당이 §4~5의 기능/AI 설명 초안을 쓰고 프론트가 전체를 다듬는 방식).

## 매몰 방지 원칙

누군가 급하게 코드에서 준비도 로직이나 API 스펙을 바꿔야 할 상황이 생기면, **먼저 해당 문서를 고치고 나서** 코드를 바꿉니다. 문서 없이 코드만 바뀌면 다른 두 사람은 그 변경을 알 방법이 없습니다. 특히 백엔드-AI서버 내부 API는 두 사람만 아는 계약이 되기 쉬우니, 바뀔 때마다 `../02-architecture/internal-api-contract.md`의 변경 이력에 남기세요.
