# 사유유형 & 판정 규칙 (FE / BE / AI 공통 계약)

> 출처: `00-context/prd.md` §2.3, §4.3. **이 문서는 세 역할이 동일한 용어와 동일한 로직을 쓰기 위한 단일 출처입니다.** 판정 로직을 구현·수정할 때는 이 문서와 PRD §4.3을 함께 갱신하세요.

## 0. 절대 원칙

> **판정은 AI가 하지 않는다.** 아래 로직은 백엔드의 `VerdictService`가 결정적(deterministic) 규칙으로 구현합니다. AI(LLM)는 증거에서 사실을 추출하고 문장을 생성할 뿐, 요건 충족 여부를 스스로 판단하지 않습니다.
>
> 이 로직은 임의로 만든 스코어링이 아니라 **금융감독원이 2026년 5월 3일 발표한 기준을 그대로 코드화**한 것입니다. 새로운 조건을 추가하고 싶다면 먼저 "이게 금감원 발표의 어느 조항에서 나온 것인가"를 확인하세요. 근거 없는 조건은 추가하지 않습니다.

## 1. 사유유형 (4종)

| 사유유형 | 트리거 예시 문구 | 대표 페르소나 | 핵심 증거 |
| --- | --- | --- | --- |
| 재화 거래 대금 | "중고 물건 판매" | P-01, P-04 | 거래 대화, 입금내역, 배송 증빙 |
| 용역 제공 대가 | "용역·알바 대가" | P-02 | 재직/계약 증빙, 입금내역, 결과물 전달 기록 |
| 채권 회수 | "빌려준 돈 회수" | P-05 | 대여 관계를 보이는 대화·송금 기록 |
| 기타/불명 | 위 세 가지에 해당하지 않음 | — | 확인 질문 1회 → 미해결 시 "사유 미확정" |

## 2. 3요건 판정

| 요건 | 정의 | 근거 |
| --- | --- | --- |
| 소액요건 | 입금액 구간 ∈ {50만원 미만, 50~300만원} | 금감원 2026.5.3 발표 — "입금액이 소액" |
| 이력요건 | 과거 지급정지 이력 없음 | 동일 — "과거 지급정지 이력 없음" |
| 생계요건 | 계좌 사용 = 주 거래 **OR** `signals.life_activity == true` | 동일 — "생계와 연관됨이 명확" |

> **'소액'의 정확한 금액 기준은 은행 내규로 비공개**입니다(PRD §14 OI-01). 서비스는 "소액에 해당할 가능성"으로만 표현하고 단정하지 않습니다 — 이 문구를 프론트/AI 출력 어디에서도 확정형으로 바꾸지 마세요.

## 3. 판정 로직 (의사코드)

```
IF NOT 이력요건:
    판정 = "별도 심사 없이 기각 가능"     ← 낙관 문구 금지
    예상 = 정식 절차 안내 + 전문가 상담 권고
ELIF 소액요건 AND 생계요건:
    판정 = "일부 지급정지 적용 가능"
    예상 = 5영업일
ELSE:
    판정 = "추가 소명 필요"
    예상 = 5+5(+3)영업일
```

확신도가 낮아 사유유형을 하나로 못 정하면(FR-031), 판정 전에 확인 질문을 1회 노출하고 응답에 따라 위 로직으로 분기합니다.

## 4. 부적격일 때의 문구 원칙

이력요건 미충족(부적격) 케이스는 **이 서비스의 신뢰를 결정하는 지점**입니다.

- 금지: "그래도 해볼만 합니다", "혹시 모르니 신청해보세요" 같은 낙관적 완곡 표현
- 허용: "과거 지급정지 이력이 있어 별도 심사 없이 기각될 수 있습니다. 정식 소명 절차(5+5+3영업일)를 안내해 드립니다."

프론트엔드는 이 문구를 그대로 노출하고 임의로 순화하지 않습니다. AI(소명서 생성 프롬프트)도 이 케이스에서 낙관적 어휘를 생성하지 않도록 프롬프트에 명시적으로 금지 조항을 둡니다(`00-context/prd.md` §10.2 참조).
