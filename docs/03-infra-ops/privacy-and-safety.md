# 개인정보 처리 및 규제 리스크

> 출처: `00-context/prd.md` §5.1, §11. 이 문서는 **전원 필독**입니다 — 개인정보 무저장 원칙은 프론트(업로드 UI 문구), 백엔드(삭제 로직), AI(마스킹 프롬프트) 세 역할 모두가 지켜야 실제로 작동합니다.

## 개인정보 처리 흐름

> **개정 (2026-08-22 이후)**: AI 파이프라인이 별도 서비스(AI-server)로 분리되면서, 이미지는 백엔드와 AI-server 두 곳을 메모리로만 거쳐 갑니다. 원래 있던 Supabase Storage 임시 저장 단계는 없앴습니다 — 경유지가 늘어날수록 무저장 원칙을 지키기 어려워지므로, 서비스 분리를 계기로 오히려 경로를 단순화했습니다.

```
[업로드]  브라우저 → 백엔드 (메모리, 디스크 저장 안 함)
              ↓
        백엔드 → AI-server (내부 API, 메모리 간 전달)
              ↓
        AI-server → LLM API 호출 (이미지 전달)
              ↓
        추출 JSON만 백엔드 세션에 보관
              ↓
        백엔드·AI-server 양쪽 모두 이미지 바이트를 요청 처리 종료 즉시 폐기
              ↓
[세션 종료 또는 30분 무활동] → 세션 데이터 전체 삭제
```

**DB에 영구 저장하는 것: 없음.** 통계용 익명 카운터(세션 수, 단계별 이탈)만 백엔드가 Supabase에 저장하며, AI-server는 Supabase에 접근하지 않습니다. 테이블 정의는 `../02-architecture/data-model.md` 참조.

## 역할별 책임

| 역할 | 책임 |
| --- | --- |
| 프론트엔드 | 업로드 화면에 "이미지는 처리 후 즉시 삭제됩니다" 안내, 개인정보처리방침 화면 제공(NFR-03 관련 UX) |
| 백엔드 | 이미지 바이트를 받은 즉시 AI-server로 전달하고 응답 수신 후 즉시 폐기(디스크에 쓰지 않음), 세션 TTL 만료 시 전체 삭제, 로그에 개인정보 미포함(NFR-08) |
| AI | AI-server가 받은 이미지도 처리 완료 즉시 폐기(디스크에 쓰지 않음), 프롬프트 단에서 전화번호·계좌번호 전체·주민번호를 추출하지 않도록 강제(§10.1 시스템 프롬프트 규칙 3) |

## 규제·법률 리스크 매트릭스

| 영역 | 잠재 이슈 | 대응 |
| --- | --- | --- |
| **변호사법** | 법률 문서 작성 대행으로 해석될 위험 | 소송 서면이 아닌 **은행 제출용 사실 진술**임을 명시. 법률적 주장·판단 문구 생성 금지(AI 프롬프트 제약) |
| **증거 조작** | 실제 범죄자가 서비스를 악용 | ① 자료를 정리만 하고 생성하지 않음 ② 허위 진술 시 형사 책임 고지 화면(프론트) ③ 금감원도 AI 위·변조 대비 추가 자료 요청 절차를 마련한 상태 |
| **개인정보보호법** | 대화 내용·금융 거래 정보 처리 | 무저장 원칙(위 흐름도). 회원가입 없음. 처리방침 화면 제공 |
| **오안내 책임** | 판정을 신뢰했다가 기각 | "진단이지 보장이 아님" 상시 배지. 부적격 판정 시 낙관 문구 금지(`01-product/reason-type-rules.md` §4) |
| **은행 업무 침해** | 심사 대행으로 오해 | 명의인 측 준비 지원임을 명시. 은행 입장에선 보완 요청 감소 이익이라는 서사 유지 |

## 상시 노출 배지 문구 (프론트엔드 필수 구현)

> "이 화면은 제출 자료를 정리하는 도구입니다. 지급정지 해제 여부는 은행 심사로 결정됩니다."

모든 단계(Stage 1~5) 화면에 이 배지를 공통으로 노출합니다. 임의로 문구를 줄이거나 톤을 바꾸지 마세요 — 이건 규제 리스크 대응 문구입니다.

## 체크리스트

- [ ] (백엔드) 이미지 바이트가 AI-server 응답 수신 후 메모리에서 즉시 해제되는지 확인 (디스크 기록 없음)
- [ ] (AI) AI-server 안에서도 이미지가 LLM API 호출 이후 즉시 폐기되는지 확인 (디스크 기록 없음)
- [ ] (백엔드) 세션 TTL 만료 로직 동작 확인, 로그에 이미지 내용·추출 텍스트 미포함 확인
- [ ] (AI) 추출 프롬프트가 전화번호/계좌번호/주민번호를 실제로 마스킹하는지 샘플 이미지로 검증
- [ ] (프론트) 상시 배지, 개인정보처리방침 화면, "허위 진술 시 형사 책임" 고지 문구 구현
- [ ] (전원) 부적격 판정 화면에 낙관적 문구가 하나도 없는지 최종 점검 (TC-04)
