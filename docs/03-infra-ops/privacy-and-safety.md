# 개인정보 처리 및 규제 리스크

> 출처: `../00-context/prd.md` §5.1, §11. 이 문서는 **전원 필독**입니다 — 완전 무저장 원칙은 프론트(리사이즈·마스킹·blob 관리), 백엔드(AI-server 전달·즉시 폐기), AI(마스킹 프롬프트·품질검사·즉시 폐기) 세 역할 모두가 지켜야 실제로 작동합니다.

## 개인정보 처리 흐름

> **개정 (2026-08-23 이후)**: AI 파이프라인이 별도 서비스(AI-server)로 분리되면서, 이미지는 백엔드와 AI-server 두 곳을 메모리로만 거쳐 갑니다. 서버(백엔드·AI-server) 어느 쪽도 이미지를 디스크·Storage·DB에 쓰지 않습니다 — 원본의 유일한 소재지는 **사용자 브라우저의 메모리(blob)**입니다.

```
[동의]    외부 LLM API 전송 · 학습 미사용 · 서버 미저장 고지 후 동의
              ↓
[리사이즈] 브라우저에서 장변 1600px 축소 (FR-020)
              ↓
[마스킹]  브라우저에서 사용자가 가릴 영역 지정 (FR-027)
              ↓
[보관]    마스킹된 blob을 브라우저 메모리에 유지  ← 원본의 유일한 소재지
              ↓
[전송]    브라우저 → 백엔드 (메모리로만 수신, 디스크 저장 안 함)
              ↓
        백엔드 → AI-server (내부 API, 메모리 간 전달)
              ↓
        AI-server → LLM API 호출 (이미지 전달)
              ↓
[해제]    LLM 응답 수신 즉시 AI-server 메모리에서 이미지 참조 해제
              ↓
[세션]    추출 JSON + 근거 참조(imageIndex, bbox)만 백엔드 세션에 보관
              ↓
        백엔드·AI-server 양쪽 모두 이미지 바이트를 요청 처리 종료 즉시 폐기
              ↓
        사용자 카드 확인(FR-028) → 소명서 생성(FR-040)
              ↓
[서식입력] 별지 제4호서식 8개 필드(신청인 4 + 계좌 4)를 사용자가 직접 입력
              ↓
        브라우저 → 백엔드 (POST /api/package/text 바디)
              ↓
        PDF 생성에만 사용 → 세션·DB·로그 어디에도 남기지 않음 (요청 바디 미로깅)
              ↓
[패키지]  백엔드 텍스트 PDF + 브라우저 이미지 페이지 병합 (FR-047)
              ↓
[세션 종료 또는 탭 닫기] → 백엔드 세션 삭제 + 브라우저 blob revoke
```

**DB에 영구 저장하는 것: 없음.** 통계용 익명 카운터(세션 수, 단계별 이탈)만 백엔드가 Supabase에 저장하며, AI-server는 Supabase에 접근하지 않습니다. 테이블 정의는 `../02-architecture/data-model.md` 참조.

## 역할별 책임

| 역할 | 책임 |
| --- | --- |
| 프론트엔드 | 업로드 전 리사이즈(장변 1600px)·마스킹 UI 제공(FR-027), blob 배열 관리 및 세션 종료·탭 이탈 시 revoke(NFR-09), "원본은 이 브라우저에만 있습니다" 안내, 개인정보처리방침 화면 제공 |
| 백엔드 | 이미지 바이트를 받은 즉시 AI-server로 전달하고 응답 수신 후 즉시 폐기(디스크에 쓰지 않음), 세션 TTL 만료 시 전체 삭제, 로그에 개인정보 미포함(NFR-08), **`/api/package/text` 요청 바디의 별지 제4호서식 8개 필드를 PDF 생성 외 어디에도 남기지 않음**(요청 바디 로깅 금지) |
| AI | AI-server가 받은 이미지도 처리 완료 즉시 폐기(디스크에 쓰지 않음), 추출 프롬프트 단에서 전화번호·계좌번호 전체·주민번호를 추출하지 않도록 강제(§10.1 시스템 프롬프트 규칙), 이미지 내 지시문을 명령으로 해석하지 않도록 방어(프롬프트 인젝션 대응), 품질 검사(FR-029)로 판독 불가 항목을 추측하지 않고 표시 |

## 규제·법률 리스크 매트릭스

| 영역 | 잠재 이슈 | 대응 |
| --- | --- | --- |
| **변호사법** | 법률 문서 작성 대행으로 해석될 위험 | 소송 서면이 아닌 **은행 제출용 사실 진술**임을 명시. 법률적 주장·판단 문구 생성 금지(AI 프롬프트 제약) |
| **증거 조작** | 실제 범죄자가 서비스를 악용 | ① 자료를 정리만 하고 생성하지 않음 ② 허위 진술 시 형사 책임 고지 화면(프론트) ③ 금감원도 AI 위·변조 대비 추가 자료 요청 절차를 마련한 상태 |
| **개인정보보호법** | 대화 내용·금융 거래 정보 처리 | 완전 무저장 원칙(위 흐름도). 회원가입 없음. 처리방침 화면 제공 |
| **오안내 책임** | 준비도 점검 결과를 승인 예측으로 오해 | 세 상태 모두에 "최종 판단은 은행이 합니다" 병기. 승인·기각 예측 문구 생성 금지(`../01-product/reason-type-rules.md` §3) |
| **은행 업무 침해** | 심사 대행으로 오해 | 명의인 측 준비 지원임을 명시. 은행 입장에선 보완 요청 감소 이익이라는 서사 유지 |
| **프롬프트 인젝션** | 업로드 이미지 속 지시문이 AI 출력을 조작 | 고정 JSON 스키마만 출력, 업로드 콘텐츠는 데이터로만 취급(FR-021), 외부 시스템 조작 권한 없음. 금융보안원 AI 에이전트 보안 보고서 근거 |
| **외부 AI 개인정보 처리** | 금융거래·대화 이미지와 제3자 정보가 외부 API로 전송 | 사전 고지·동의(§5.1), 전송 전 사용자 마스킹(FR-027), 제공자의 비학습·최소 보관 설정 적용, 서버 미저장 |

## 상시 노출 배지 문구 (프론트엔드 필수 구현)

> "이 화면은 제출 자료를 정리하는 도구입니다. 지급정지 해제 여부는 은행 심사로 결정됩니다."

모든 단계(Stage 1~5) 화면에 이 배지를 공통으로 노출합니다. 임의로 문구를 줄이거나 톤을 바꾸지 마세요 — 이건 규제 리스크 대응 문구입니다.

## 체크리스트

- [ ] (프론트) 업로드 전 리사이즈·마스킹 UI 구현, blob revoke 로직 확인 (새로고침·탭 종료 시 원본 소실 안내 포함)
- [ ] (백엔드) 이미지 바이트가 AI-server 응답 수신 후 메모리에서 즉시 해제되는지 확인 (디스크 기록 없음)
- [ ] (AI) AI-server 안에서도 이미지가 LLM API 호출 이후 즉시 폐기되는지 확인 (디스크 기록 없음)
- [ ] (백엔드) 세션 TTL 만료 로직 동작 확인, 로그에 이미지 내용·추출 텍스트 미포함 확인
- [ ] (백엔드) `/api/package/text` 요청 바디(신청인 성명·생년월일·주소·연락처, 계좌 4개)가 로그·세션·DB에 남지 않는지 확인 — 접근 로그 필터에 이 경로의 바디를 제외
- [ ] (AI) 추출 프롬프트가 전화번호/계좌번호/주민번호를 실제로 마스킹하는지 샘플 이미지로 검증
- [ ] (AI) 이미지 내 지시문 문구가 포함된 샘플로 프롬프트 인젝션 방어 검증 (`../04-testing/test-cases-and-demo.md` TC-10)
- [ ] (프론트) 상시 배지, 개인정보처리방침 화면, "허위 진술 시 형사 책임" 고지 문구 구현
- [ ] (전원) "은행 확인 필요" 화면에 낙관적 문구가 하나도 없는지 최종 점검 (TC-04)
