## 1. ⚠️ 3면 타임라인에 미확인 카드가 들어가는지 정해져 있지 않습니다

F8-01 표의 3면 행입니다.

| 면 | 항목 | 정렬 |
| --- | --- | --- |
| **3면** | 일시 · 행위 주체 · 요약 · 금액 | `occurred_at` 오름차순, 동시각은 F5-01 tie-break |

**어떤 카드를 싣는지가 없습니다.** 다른 면은 전부 정해져 있어서 3면만 비어 있습니다.

| 면 | 미확인(`pending`) 카드 |
| --- | --- |
| 2면 | **제외** — F4-06 "confirmed=true 카드만 F7-01 입력으로 전달한다" |
| **3면** | **정해진 바 없음** |
| 4면 | **제외** — 카드 단위 목록이고 `pending`은 4면에 없다고 2026-08-25 정정에 적혀 있습니다 |

그대로 두면 **같은 묶음 안에서 면끼리 어긋납니다.** 실제로 지금 그렇습니다 — 카드 4장 중 1장만 확인한 상태에서 2면은 문장 3개를 빼고 4면은 1줄인데, 3면만 5줄이 그대로 나옵니다.

**제외를 권합니다.** F4-06의 수용 기준은 "미확인 카드의 날짜·금액이 소명서 **본문**에 나타나지 않음"이라 문자 그대로는 2면만 가리키지만, 막으려는 것은 *확인하지 않은 AI 판독이 은행에 가는 것*입니다. 3면은 일시와 금액만 모아둔 면이라 그 값이 가장 날것으로 실립니다.

**프론트는 그동안 제외로 두었습니다.** 미리보기 3면을 확인된 카드만으로 그립니다. 반대로 정하시면 한 줄 되돌립니다.

| --- | --- | --- |
| 1 | F8-01 3면 행에 미확인 카드 처리를 명시 | **PDF 구현 착수 전** — 서버가 만드는 3면과 프론트 미리보기가 갈리면 안 됩니다 |

## 2. F10-05 자영업자 안내 트리거에 없는 입력이 들어 있습니다

| 항목 | 내용 |
| --- | --- |
| 트리거 | 계좌 사용 = '주 거래 계좌다' **+ 거래 성격이 사업 관련** |

**"거래 성격이 사업 관련"을 판정할 입력이 없습니다.** 문진의 거래 성격(`kind`)은 중고 물건 판매 / 용역·알바 대가 / 빌려준 돈 회수 / 잘 모르겠어요 4개뿐이고, `api-contract.md`의 enum도 같습니다. 사업 여부를 묻는 문항이 없습니다.

**프론트는 '주 거래 계좌예요'만 보고 띄웁니다.** 안내 문구 자체가 "**사업 계좌라면** 미리 준비해요"로 시작해서, 해당 없는 사용자가 봐도 오안내가 되지는 않습니다.

| 안 | 내용 |
| --- | --- |
| **A (권장)** | 트리거를 **'주 거래 계좌다'** 로 정정. 문구가 조건부라 넓게 잡아도 해가 없고, 사업자에게 놓치는 경우가 줄어듭니다 |
| B | 사업 여부 문항을 신설 — `kind` enum 변경이라 **계약·AI 분류 프롬프트까지 영향**이 갑니다. 이 안내 하나를 위해서는 과합니다 |

| # | 항목 |
| --- | --- |
| 1 | A/B 판단 후 회신. A면 `spec.md` F10-05 트리거 행 정정 |
