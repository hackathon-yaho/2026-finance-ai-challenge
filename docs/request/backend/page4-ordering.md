# [프론트 → 백엔드] 4면 정렬 기준 "5면 이미지 순서와 일치"가 성립하지 않습니다

> **상태: ⏳ 회신 대기** (요청 2026-08-25)
> 회신은 `../../response/frontend/page4-ordering.md`에 들어옵니다.
> **막고 있는 작업**: 없음 — 임시 정렬로 두고 진행 중입니다. **PDF 구현 착수 전에만 확정되면 됩니다.**

- 작성: 프론트엔드 · 2026-08-25
- 관련 문서: `../../00-context/spec.md` F8-01 "면별 항목·정렬 기준", `../../02-architecture/api-contract.md` 카드 스키마
- 배경: 회신(`../../response/frontend/draft-preview-and-edit.md` §3)에서 4면 = **A(올린 자료의 목차)** 로 확정하고 면별 기준을 정의해 주셨습니다. 그걸 미리보기에 반영하다 발견했습니다.

## 1. 무엇이 어긋나나

F8-01 표가 이렇습니다.

| 면 | 항목 | 정렬 |
| --- | --- | --- |
| **4면** | 순번 · 자료 유형(`source_type` 한글 라벨) · 확인된 일시 · 한 줄 요약 | **5면 이미지 페이지 순서와 일치** |

**항목은 카드 단위인데 정렬은 이미지 단위입니다.** 셋이 1:1이 아닙니다.

| # | 상황 | 결과 |
| --- | --- | --- |
| 1 | **이미지 1장에서 카드가 여러 장 나옴** — 계약의 `event_id`가 `evt_{image_index}_{n}`인 이유입니다. 대화 캡처 안에 송금 알림이 같이 찍힌 경우 | 4면 2줄 ↔ 5면 1장 |
| 2 | **미확인 카드는 문서에서 빠지지만**(F4-06) 그 원본 이미지는 5면에 그대로 있음 | 4면 0줄 ↔ 5면 1장 |
| 3 | **텍스트 직접 입력 카드는 이미지가 없음** (`source_image_index: null`) | 4면 1줄 ↔ 5면 0장 |

1번은 `source_type`을 **이벤트 단위로 옮긴 결정**(2026-08-25, `card-source-type.md`)의 직접적인 결과입니다. "한 이미지에 유형이 섞이는 경우가 흔하다"는 게 그때 근거였는데, 그렇다면 **4면 한 줄이 이미지 하나에 대응한다는 전제도 같이 깨집니다.**

## 2. 선택지

| 안 | 4면 구성 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A** | **이미지 단위** 1장 = 1줄 | 5면과 정확히 1:1 | "자료 유형·확인된 일시"를 이미지 대표값으로 정해야 함 — 유형이 섞인 이미지에서 무엇을 쓸지 애매 |
| **B (권장)** | **카드 단위** + `source_image_index` 오름차순. 줄마다 **"원본 n번"** 표기 | 카드가 여러 장인 이미지도 그대로 표현. 대조가 가능 | 4면 줄 수 ≠ 5면 장 수 |
| C | 카드 단위 + **5면도 확인된 카드의 원본만** | 개수가 맞음 | 미확인 자료의 원본이 제출본에서 빠짐 — 사용자가 올린 걸 우리가 임의로 뺌 |

**B를 권합니다.** 4면은 **목차**이고, 담당자가 필요한 건 "이 항목이 몇 번째 원본에서 나왔나"입니다. 줄 수와 장 수가 다른 건 목차에서 자연스럽습니다 — 한 장에서 두 사실이 나올 수 있으니까요.

**C는 반대합니다.** 사용자가 올린 자료를 확인하지 않았다는 이유로 제출본에서 빼면, 은행이 볼 수 있었던 정황이 사라집니다. 미확인은 "본문에 안 쓴다"이지 "원본을 안 낸다"가 아니라고 봅니다 — F4-06도 "미확인 카드의 날짜·금액이 **본문에** 나타나지 않음"까지만 정하고 있습니다.

## 3. 텍스트 직접 입력 카드는 별도로 정해야 합니다

어느 안을 고르든 **`source_image_index: null`인 카드**(F3-04 경로)가 남습니다. 대응할 이미지가 없습니다.

제안: 4면 목록에는 **넣되 "원본 n번" 표기 없이** 두고, 자료 유형 자리에 **"본인 서술"** 로 적습니다. 근거 유형이 `user_text`라 소명서에도 "본인 진술" 배지가 붙는 것과 같은 취급입니다.

## 4. 그동안 프론트는 이렇게 둡니다

미리보기 4면을 **`source_image_index` 오름차순**(B안)으로 정렬하고, 이미지가 없는 카드는 뒤로 보냈습니다. 확정되면 그쪽으로 맞춥니다. **"원본 n번" 표기는 아직 넣지 않았습니다** — 확정 전에 넣으면 A안일 때 지워야 합니다.

## 5. 백엔드가 해야 할 것

| # | 항목 | 시점 |
| --- | --- | --- |
| 1 | A/B/C 판단 후 `spec.md` F8-01 4면 행 정정 | **PDF 구현 착수 전** |
| 2 | §3 텍스트 입력 카드의 4면 표기 확정 | 위와 같이 |
| 3 | B안이면 **카드에 "몇 번째 원본"을 표기**하는 형식 확정 (`source_image_index`를 그대로 쓸지, 1-base로 바꿀지) | 위와 같이 |

> 3번은 사소해 보이지만 **`source_image_index`가 0-base**입니다(계약). 화면·문서에 "원본 0번"이라고 적을 수는 없어서, 표시용 번호를 어디서 만들지 정해두는 편이 낫습니다.
