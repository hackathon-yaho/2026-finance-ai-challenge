## 1. 텍스트 5종 PDF 생성 주체 (회신 필요 — 가장 급함)

`spec.md` 총괄표에서 **F8-01(텍스트 5종 PDF 생성) 담당이 `C`(프론트)** 로 적혀 있는데, 다른 4개 문서는 전부 **서버 생성**을 전제합니다.

| 문서 | 내용 |
| --- | --- |
| `spec.md` F7-06 | "①~④,⑥ = **서버 PDF 생성**(F8-01) / ⑤ = 브라우저가 이미지 페이지 생성" |
| `spec.md` F8-01 본문 | "라이브러리: **서버 OpenPDF 또는 Apache PDFBox** / 클라이언트 pdf-lib", "**Render 컨테이너에 한글 폰트**가 없으면 전부 깨진다" |
| `api-contract.md` | `GET /api/package/text` → `application/pdf` |
| `deployment-and-uptime.md` | 백엔드 체크리스트에 "한글 폰트(`fonts-nanum`) 설치" |

**백엔드 의견**: 총괄표 담당 칸의 표기 오류로 보이며, 서버가 텍스트 5종을 만들고 프론트가 `pdf-lib`으로 원본 이미지 페이지를 병합하는 F7-06 분담이 맞다고 생각합니다. 다만 프론트 작업량에 직결되는 문제라 확인 없이 진행하지 않겠습니다.

어느 쪽으로 정하든 **정한 쪽으로 `spec.md` 총괄표와 `api-contract.md`를 함께 고치겠습니다.**

### 서버 생성으로 확정될 경우 함께 필요한 변경

`GET /api/package/text`를 **`POST`로 바꿔야 합니다.**

PRD §4.4 별지 제4호서식 필드 매핑상 아래 값들이 "사용자 직접 입력(서비스 미저장, PDF 생성 시에만 사용)"인데, `GET`에는 이 값을 담을 자리가 없습니다.

- 신청인 성명 · 생년월일 · 주소 · 연락처
- 지급정지 계좌: 금융회사 / 개설점포 / 예금종별 / 계좌번호

백엔드는 이 값을 **PDF 생성에만 쓰고 세션·DB·로그 어디에도 남기지 않습니다.**

## 2. F5-02 중복 이벤트 병합 승인 엔드포인트 (회신 필요)

`spec.md` F5-02는 "**자동 확정하지 않는다.** 병합 후보로 사용자에게 제시하고 **승인받은 경우에만** 병합한다"인데, `api-contract.md`에 승인 엔드포인트가 없습니다.

**백엔드 제안**: `POST /api/timeline/merge` — 요청 `{ mergeGroupIds: ["evt_003", "evt_007"], approved: true }`, 응답은 갱신된 타임라인.

회신 전까지 백엔드는 **병합 후보 산출까지만** 구현하고 `GET /api/timeline` 응답에 후보 목록을 담아두겠습니다. (F5-02는 스코프 컷 순서 4번이라 일정이 밀리면 버려도 되는 항목입니다.)

## 3. 확정 통보 2건 (프론트 구현에 영향)

### 3-1. 세션 식별자는 **커스텀 헤더 `X-Session-Hash`** 입니다

`api-contract.md`에 "쿠키 vs 커스텀 헤더는 FE/BE가 착수 전 확정 (→ TODO)"으로 남아 있던 항목입니다. 헤더로 확정했습니다.

- 프론트는 `POST /api/session` 응답의 `sessionHash`를 **이후 모든 요청 헤더 `X-Session-Hash`에 실어** 보내주세요.
- `credentials: 'include'`는 필요 없습니다 (쿠키를 쓰지 않습니다).
- 세션 만료 시 **`410 Gone` + `{"error":"SESSION_EXPIRED"}`** 가 내려갑니다. 원본 이미지는 서버에 없었으므로 **재업로드가 필요하다**는 안내가 함께 나가야 합니다.

프론트가 정적 호스팅, 백엔드가 Render로 도메인이 달라 쿠키를 쓰면 `SameSite=None; Secure` + 브라우저별 추적 방지 정책에 걸릴 위험이 있어 헤더를 택했습니다. `spec.md` F1-01의 "HttpOnly 쿠키" 표기도 함께 고치겠습니다.

### 3-2. 이의제기 기한(FR-014)은 **백엔드가 계산**해 내려줍니다

`POST /api/intake` 응답에 필드를 추가합니다.

```json
{
  "ok": true,
  "nextStage": 2,
  "deadline": {
    "date": "2026-11-01",          // 공고일 미입력 시 null
    "daysLeft": 42,                 // 공고일 미입력 시 null
    "notice": "이의제기 기한까지 42일 남았습니다. (2026-11-01)"
  }
}
```

- `notice` 문구는 PRD §4.1의 4가지 분기 문구를 **그대로** 내려줍니다. 프론트에서 순화하거나 줄이지 마세요 — 법 제7조 근거의 안내 문구입니다.
- 기한 경과가 확실한 경우에도 "불가능"이라고 단정하지 않고 금융회사·전문가 확인을 권하는 문구가 나갑니다.

### 3-3. FR-028 게이팅을 **백엔드도 서버 측에서 거부**합니다

`api-contract.md`는 게이팅 주체를 프론트로만 적어뒀는데, 백엔드도 같은 조건을 검사하도록 확정했습니다(2026-08-23).

- 날짜 또는 금액이 `low` 신뢰도인 카드가 `pending`으로 남은 채 `/api/readiness`를 호출하면 **`409` + `{"error":"UNCONFIRMED_FIELDS"}`** 가 내려갑니다.
- 프론트 차단은 사용자 경험, 서버 거부는 데이터 무결성 목적입니다 — 확인 안 된 low 신뢰도 금액으로 준비도가 산출되면 틀린 서류가 은행에 갑니다(F4-06 필요성).
- **그 외 미확인 카드는 서버가 통과시킵니다.** 준비도 산출 입력에서 제외될 뿐이며, "확인하지 않은 자료 n건은 문서에 포함되지 않습니다" 경고는 기존대로 프론트가 노출합니다.

정상 흐름이라면 프론트가 먼저 막으므로 이 409는 뜨지 않습니다. 방어선이 하나 더 있다는 뜻으로만 봐주세요.

### 3-4. `/api/evidence`는 **이미지 1장씩 병렬로** 호출해 주세요

`spec.md` F3-03이 "SSE 또는 폴링으로 파일별 완료를 즉시 반영"을 요구하는데, 계약의 `/api/evidence`는 일괄 응답이라 판독 8~14초 동안 화면이 빕니다("이 구간이 비면 사용자가 이탈한다" — F3-03 개발 주의).

SSE 인프라를 새로 만드는 대신 **1장씩 병렬 호출**로 해결하기로 확정했습니다(2026-08-23).

- 응답이 도착하는 순서대로 파일별 "읽음 / 실패"를 칠 수 있습니다.
- AI-server도 이미지별 병렬 호출(최대 4 동시)이 전제입니다(F4-01).
- 백엔드는 호출이 나뉘어도 **세션당 누적 10장 제한**을 유지합니다. 11장째는 `400`입니다.

### 3-5. 응답 필드 2개가 추가됩니다

계약에 정의가 없어 프론트가 알 방법이 없던 값들입니다.

| 필드 | 위치 | 용도 |
| --- | --- | --- |
| `demoMode` (boolean) | `POST /api/session` 응답 | `true`면 전 화면 상단에 **"예시 데이터 사용 중 — 실제 AI 분석 결과가 아닙니다"** 배지 고정 (F11-03) |
| `smallAmountNotice` (string) | `POST /api/readiness` 응답 | PRD §4.3 소액 안내 카드 문구 |

`smallAmountNotice`는 **판정이 아니라 정보 제공**입니다. 입금액에 따라 문구가 달라지지 않는 고정 문구이며(소액 여부를 서비스가 판정하지 않기 때문입니다 — §14 OI-01), "소액에 해당하니 유리하다"처럼 단정적으로 바꾸지 말아주세요.

## 4. 참고 — 백엔드가 CORS에 열어둘 항목

허용 헤더에 `X-Session-Hash`를 포함합니다. **프론트 배포 도메인이 확정되면 알려주세요** — 허용 origin에 등록해야 요청이 통과합니다.
