## 1. `POST /api/draft/revise` — 제외한 문장은 응답 배열에서 아예 빠집니다

계약에 `excluded` 상태를 표시할 필드가 따로 없어서, `excluded: true`로 보낸 문장은 응답의 `sentences` 배열에서 **제거**하는 방식으로 구현했습니다. 즉:

- 요청으로 문장을 제외하면 → 다음 응답의 `sentences`엔 그 `sentenceId`가 없습니다
- 되돌리려면(다시 포함) 프론트가 그 문장의 **원래 텍스트를 기억해뒀다가** 같은 `sentenceId`로 다시 `POST /api/draft/revise`를 호출해 `excluded: false`로 보내주세요 — 서버는 삭제하지 않고 세션에 계속 들고 있어서, `excluded: false`만 보내면 텍스트 그대로 복원됩니다

**확인 부탁**: 프론트 화면에서 "제외" 토글을 눈에 보이게(취소선 등) 유지하려면 원본 텍스트를 클라이언트에서 계속 들고 있어야 합니다 — 서버 응답만 보고는 "제외됐다"는 사실 외에 그 문장이 뭐였는지 알 수 없습니다(배열에서 아예 빠지므로).

## 2. `DRAFT_FAILED`(502) 오류 코드가 새로 생겼습니다

`/api/draft` 호출이 AI-server 쪽에서 재시도 1회 후에도 실패하면 이 코드로 내려갑니다. `fallback` 필드는 없습니다(대체 경로가 없어서요 — 재시도 방법은 사용자가 `/api/draft`를 다시 호출하는 것뿐입니다).

```json
{ "error": "DRAFT_FAILED", "message": "소명서 생성에 실패했습니다." }
```

**확인 부탁**: "잠시 후 다시 시도해주세요" 같은 안내 + 재시도 버튼 정도로 처리하시면 됩니다.
