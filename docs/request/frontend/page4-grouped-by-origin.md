## 무엇을 바꿨나

사용자가 실제 생성된 PDF를 검토하다가 지적했습니다 — **3면(시간순 타임라인)과 4면(증빙자료 목록)이 열 구성만 다를 뿐 사실상 같은 표**였습니다. 둘 다 **카드 단위**라, 캡처 한 장에서 카드가 여러 개 나오면(예: 대화 캡처 1장 → 3장) 3면·4면에 똑같이 여러 줄로 흩어졌습니다. 4면이 "올린 자료의 목차"(F8-01)라는 취지에 안 맞았습니다 — 목차인데 카드 수만큼 줄이 늘어나니 "내가 뭘 제출했는지"에 답이 안 됐습니다.

그래서 **4면을 원본(첨부) 단위로 재구성**했습니다. `source_image_index`가 같은 카드끼리 한 줄로 묶습니다.

## 새 규칙 (`spec.md` F8-01 "면별 항목·정렬 기준"에 반영 완료)

**그룹핑 키**: `source_image_index`(0-base). 같은 값끼리 묶고, `null`(F3-04 텍스트 직접 입력 카드)은 별도로 묶어 **맨 뒤**에 "본인 서술" 한 줄로.

**한 줄의 구성**:
- **자료 유형**: 그 원본 첫 카드의 `source_type` 라벨 (한 원본은 보통 한 유형이라 첫 카드 기준으로 충분합니다)
- **확인된 일시**: 그룹 카드들의 `occurred_at` 중 **아는 값만 모아 범위**로 표기 (`A ~ B`). 값이 하나뿐이거나 전부 같으면 그 값 하나만, 전부 모르면 "시각 미상", 일부만 모르면 범위 뒤에 "(시각 미상 N건 포함)"
- **요약**: 카드가 **한 장**이면 그 카드의 요약 그대로. **여러 장**이면 개별 요약 대신 **"N건 확인됨"**만 — 개별 사실은 이미 3면에 있어 4면에서 다시 나열하지 않습니다. (처음엔 "N건 확인됨 · 예: {대표 요약}"도 넣어봤는데, 일시 범위+개수+예시를 한 열에 다 넣으니 저희 쪽 표 렌더러가 잘라 "예: …"처럼 내용 없는 줄이 나와 뺐습니다.)
- **원본**: 종전과 동일, "원본 n번"(1-base) / "본인 서술"

**순서**: `source_image_index` 오름차순, `null` 그룹은 맨 뒤. (원본 개수만큼만 줄이 생기므로 순번=원본 등장 순서와 사실상 같아집니다.)

## 확인 부탁드리는 것

1. **S04-2 "① 정리해서 보기" 화면이 4면을 별도 HTML로 그리고 있다면, 위 그룹핑으로 맞춰주세요.** `spec.md` F8-01이 "같은 면을 두 사람이 각자 그린다 · PDF가 단일 출처"라고 명시해둔 부분이라, 여기서 어긋나면 `evt_intake_when`·3면 미확인 카드 때와 같은 유형의 미리보기-실제 파일 불일치가 다시 생깁니다.
2. **"② 실제 문서" 뷰(pdf.js로 실제 PDF 렌더)는 영향 없습니다** — 저희가 만드는 PDF 바이트를 그대로 그리는 뷰라 자동으로 반영됩니다.
3. API 계약(요청/응답 JSON 스키마)은 **변경 없습니다.** 4면은 서버가 PDF 안에 텍스트로 그리는 것뿐이라, 프론트가 이미 갖고 있는 카드 목록(각 `/api/evidence` 응답에서 받은 것)에서 같은 그룹핑 로직을 프론트 쪽에서도 구현해야 정리해서 보기가 일치합니다.

백엔드 쪽 변경은 `PackageServiceImpl.buildEvidenceRows` 하나이고, 테스트·문서(`spec.md`, `phase-5-draft-package.md`)까지 반영해 이미 커밋했습니다.
