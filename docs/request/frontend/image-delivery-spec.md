# [AI → 프론트] 실제로 전송되는 이미지의 해상도·포맷을 알려주세요

> **상태: ⏳ 회신 대기** (요청 2026-08-25)
> 회신은 `../../response/ai/image-delivery-spec.md`에 들어옵니다.
> **막고 있는 작업**: 없음 — **급하지 않습니다.** 이미 대기 중인 4건을 먼저 처리하세요. 이건 답이 늦어도 AI 작업이 멈추지 않고, 다만 늦게 오면 제 품질 측정치가 실전을 덜 정확하게 예측합니다.

- 작성: AI · 2026-08-25
- 관련 문서: `../../00-context/spec.md` F3-01, `../../00-context/prd.md` FR-020, `../../../ai-server/evals/README.md`

## 왜 묻는가

AI 품질을 숫자로 재는 **고정 평가 세트**를 만들었습니다(`ai-server/evals/`, 합성 캡처 23건). 여기서 나온 날짜·금액 정확도가 PRD §1.4의 목표(90%)를 넘는지로 배포 가부를 판단합니다.

문제는 **평가 세트의 이미지 조건이 실제 전송 조건과 다르면 그 숫자가 실전을 예측하지 못한다**는 점입니다. 같은 프롬프트라도 해상도가 낮으면 판독이 무너지고, 그때 저는 프롬프트를 고치려 들 텐데 원인은 프롬프트가 아니게 됩니다.

이건 가정이 아니라 **이 프로젝트에서 이미 한 번 일어난 일**입니다. `spec.md` F3-01 개발 주의:

> 처리 ①(1600px 리사이즈)을 빠뜨리면 전송 해상도가 **사용자 화면 크기와 DPR에 좌우된다.** 데스크톱 1x에서 세로 캡처가 **199×431까지 줄어** 계좌번호·시각·금액을 사람도 못 읽는 사례가 실제로 있었다(2026-08-24 수정). **F4-01 판독 정확도가 낮으면 여기부터 확인할 것**

수정되었다고 적혀 있으니 지금은 괜찮을 텐데, **실제 값을 확인해서 평가 세트를 거기에 맞추고 싶습니다.**

## 알려주실 것 — 3개면 됩니다

업로드 화면에서 캡처 한 장을 실제로 전송해 보시고, **전송 직전 blob의 값**을 알려주세요. 개발자 도구 Network 탭이나 `console.log`면 충분합니다.

| 항목 | 예시 | 왜 필요한가 |
| --- | --- | --- |
| **가로×세로 픽셀** | `976 × 1600` | 평가 세트 캔버스를 같은 크기로 맞춥니다 |
| **포맷** | `image/png` 또는 `image/jpeg` | JPEG면 압축 품질(0.8 등)도 알려주세요 — 압축 아티팩트가 작은 글자 판독에 영향을 줍니다 |
| **파일 크기** | `약 420KB` | 계약 상한 10MB 대비 여유 확인 |

**세로로 긴 모바일 캡처 기준**으로 부탁드립니다. 실제 사용자가 올릴 형태가 그것이기 때문입니다.

> 개인 캡처를 쓰지 마세요. 아무 앱 화면이나 임의 스크린샷이면 됩니다 — **값만 필요하고 이미지는 필요하지 않습니다.**

## 참고 — 제 현재 가정

지금 평가 세트는 **720×1180 PNG, 본문 글자 약 27px**로 만들어 두었습니다. 실제 모바일 캡처(1080×2340, 본문 약 40px)를 장변 1600px로 줄이면 본문이 약 27px가 되므로 **글자 크기 기준으로는 비슷할 것으로 추정**하고 있습니다.

**다만 이건 계산으로 추정한 값이지 확인한 값이 아닙니다.** 실제 값이 오면 그때 캔버스를 맞추고, 차이가 크면 이미지를 재생성해 다시 측정하겠습니다.

## 확인해 주시면 좋은 것 (선택)

`spec.md` F3-01 처리 ①의 **장변 1600px 리사이즈가 지금 코드에 실제로 들어가 있는지** 한 번만 봐주세요. 위 199×431 사례가 이것을 빠뜨려서 생긴 것이고, 이게 빠지면 **AI 판독 정확도가 프롬프트와 무관하게 무너집니다.** 이미 들어가 있다면 답에 "적용됨" 한 줄만 적어 주시면 됩니다.
